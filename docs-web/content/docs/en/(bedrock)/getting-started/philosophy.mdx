## Why Bedrock Exists

In the era of vibe coding and agentic coding, AI assistants have become powerful development tools. However, without clear conventions and guardrails, AI-generated code often suffers from poor extensibility, inconsistent patterns, and unmaintainable structures.

Writing `AGENTS.md` files for every project is tedious and inefficient. Bedrock was born to solve this problem — it provides a standardized modular development framework that works seamlessly with both human developers and AI coding assistants.

## Origins

Bedrock's design is inspired by the modular development approaches of Django and Odoo. Both frameworks allow developers to focus on business logic without getting bogged down in framework internals.

However, Django's heavyweight approach feels over-engineered for non web app use cases. Bedrock provides a lightweight alternative that captures the best of modular design while staying lean and framework-agnostic.

## Core Principles

### 1. Modular by Default

Every module is a self-contained unit with its own entities, schemas, services, exceptions, and lifecycle hooks. Modules organize through explicit dependencies, preventing code coupling and structural chaos.

```text
bedrock_app/
├── __init__.py
├── manifest.yaml
├── entities.py
├── schemas.py
├── service.py
├── exc.py
└── bootstrap.py
```

### 2. Convention Over Configuration

Bedrock uses agreed-upon file structures and naming conventions to guide developers. Instead of configuring everything from scratch, you follow the pattern — and the framework does the rest.

This approach benefits both humans and AI:
- Humans spend less time on boilerplate decisions
- AI assistants generate more accurate code because the architecture is unambiguous

### 3. Lifecycle Management

Modules define lifecycle hooks that execute at the right time during initialization and shutdown. This ensures proper loading order, resource cleanup, and integration setup.

### 4. Explicit Dependencies

Modules declare their dependencies in `manifest.yaml`. The runtime validates the dependency graph, detects cycles, and computes a deterministic load order. No magic, no import-time side effects.

### 5. AI-Ready Architecture

Bedrock is designed from the ground up to work with AI coding assistants:

- **Predictable structure** — AI can reason about where code belongs
- **Clear boundaries** — AI knows what each layer should contain
- **Manifest-driven** — AI understands module relationships without scanning code
- **Convention-based** — AI follows patterns instead of inventing them

## Design Philosophy

### Loose Coupling with the Business

Bedrock intentionally minimizes coupling with business logic. The core framework provides patterns and infrastructure — it does not dictate what your application does.

Features and capabilities are added through extension modules, not by modifying Bedrock's core. This keeps the framework stable and your business logic independent.

### One Framework, Many Use Cases

Bedrock is not limited to web applications. The same modular patterns work for:

- Web applications (FastAPI, or any HTTP framework)
- CLI tools
- Background workers
- AI agents and assistants
- Internal tooling

The module system provides structure regardless of the runtime context.

## Vision

Bedrock aims to be the foundation for building maintainable, extensible Python applications — whether you're a solo developer, a team, or an AI assistant writing code.

By establishing clear conventions and providing a robust module system, Bedrock helps you:

- Ship faster with less boilerplate
- Maintain code quality as the project grows
- Collaborate effectively with AI tools
- Keep business logic separate from framework concerns
