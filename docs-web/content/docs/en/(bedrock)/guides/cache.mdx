Bedrock ships a first-party cache system with pluggable backends, typed namespaces, and distributed locks. The whole subsystem lives under `bedrock.contrib.cache`.

## Quick Start

```python
from bedrock.contrib.cache import cache

# Store a value (auto-configures with in-memory backend)
cache.set("user:123", {"name": "Alice"}, ex=300)

# Retrieve it
user = cache.get("user:123")
print(user)  # {"name": "Alice"}

# Async variants
await cache.aset("user:456", {"name": "Bob"}, ex=600)
user = await cache.aget("user:456")
```

That's the core loop. The rest of this page covers configuration, the full API, and advanced patterns.

## Configuration

The cache service uses a dynamic backend registry. The in-memory backend is available by default. Redis requires the optional `redis` dependency.

### Backend Selection

Set `CACHE_BACKEND` to a registered backend name; it defaults to `memory`. The cache module's `ready` hook calls `cache.configure()`, and the first operation in a script that never configured the cache does the same, so both pick up `CACHE_BACKEND`. Each backend reads its own settings from its prefix (`CACHE_MEMORY_`, `CACHE_REDIS_`):

```bash
CACHE_BACKEND=redis
CACHE_REDIS_URL=redis://localhost:6379/0
CACHE_REDIS_KEY_PREFIX=myapp:
```

An unknown name fails startup with `BackendNotConfiguredError`, whose message says the name came from `CACHE_BACKEND`. A custom backend registered in an `on_load` hook can be selected this way, because `ready` runs after every module was loaded.

Pass a name to choose in code instead; an explicit name ignores `CACHE_BACKEND`:

```python
from bedrock.contrib.cache import cache

cache.configure()         # backend named by CACHE_BACKEND (memory when unset)
cache.configure("memory")
cache.configure("redis")  # requires: uv add bedrock-core[cache-redis]
```

### Custom Settings

Pass a settings instance to override defaults:

```python
from bedrock.contrib.cache import cache
from bedrock.contrib.cache.backends.redis import RedisCacheSettings

settings = RedisCacheSettings(
    url="redis://localhost:6379/1",
    key_prefix="myapp:",
)
cache.configure("redis", settings=settings)
```

### Registering Custom Backends

A custom backend implements the `CacheBackend` protocol, either by inheriting it (directly or through an existing backend) or structurally. Register extensions from `bootstrap.py:on_load`:

```python
from bedrock.contrib.cache import register_backend
from bedrock.contrib.cache.backends.memory import InMemoryBackend


class MyCustomBackend(InMemoryBackend):
    """Project-specific implementation inheriting the complete memory backend."""


def on_load() -> None:
    """Register the project backend once during module loading."""
    register_backend("custom", MyCustomBackend)
```

Select it with `cache.configure("custom")` after registration. `register_backend()` also accepts a factory that takes `settings=`. `configure()` checks that the created object has every `CacheBackend` member (names only, not signatures), so cover a custom backend with your own contract tests.

To keep a backend module and its SDK out of memory until it is selected, register a path instead:

```python
from bedrock.contrib.cache import register_backend_lazy


def on_load() -> None:
    """Register the backend by path; nothing is imported until cache.configure("acme") runs."""
    register_backend_lazy("acme", "acme_cache.backend:AcmeBackend", install_requirement="acme-cache[redis]")
```

Registering the same object or path again under its name does nothing. A different backend under a taken name, including the built-ins `memory` and `redis`, raises `DuplicateRegistrationError`; an empty name, malformed path, or non-callable raises `InvalidRegisteredClassError`. Both come from `bedrock.common.registry`. `configure()` raises `BackendNotConfiguredError` when the name is unknown, the module or its SDK cannot be imported (the message names the install requirement, e.g. `bedrock-core[cache-redis]`), or the created object does not implement `CacheBackend`; the [provider](./provider) error is the cause. Other exceptions from the backend constructor propagate unchanged.

## CacheService API Reference

The `cache` singleton is a `CacheService` instance. All access goes through this object.

### Core Operations

| Method | Signature | Description |
|--------|-----------|-------------|
| `cache.get()` | `get(key, default=None, type_=None, coder=None) → Any` | Retrieve a cached value |
| `cache.aget()` | `aget(key, default=None, type_=None, coder=None) → Any` | Async variant of `get` |
| `cache.set()` | `set(key, value, ex=None, px=None, ea=None, coder=None) → None` | Store a value |
| `cache.aset()` | `aset(key, value, ex=None, px=None, ea=None, coder=None) → None` | Async variant of `set` |
| `cache.delete()` | `delete(key) → bool` | Remove a key |
| `cache.adelete()` | `adelete(key) → bool` | Async variant of `delete` |
| `cache.exists()` | `exists(key) → bool` | Check if key exists |
| `cache.aexists()` | `aexists(key) → bool` | Async variant of `exists` |
| `cache.clear()` | `clear(prefix=None) → int` | Remove all entries (optionally by prefix) |
| `cache.aclear()` | `aclear(prefix=None) → int` | Async variant of `clear` |

### Batch Operations

| Method | Signature | Description |
|--------|-----------|-------------|
| `cache.get_many()` | `get_many(keys) → dict[str, Any]` | Retrieve multiple keys |
| `cache.aget_many()` | `aget_many(keys) → dict[str, Any]` | Async variant |
| `cache.set_many()` | `set_many(mapping, ex=None, px=None, ea=None, coder=None) → None` | Store multiple pairs |
| `cache.aset_many()` | `aset_many(mapping, ex=None, px=None, ea=None, coder=None) → None` | Async variant |

`get_many()` and `aget_many()` omit missing keys and always use the default decoder; use individual `get()` calls for custom coders.

### Numeric Operations

| Method | Signature | Description |
|--------|-----------|-------------|
| `cache.incr()` | `incr(key, delta=1) → int` | Increment a numeric value |
| `cache.aincr()` | `aincr(key, delta=1) → int` | Async variant |
| `cache.decr()` | `decr(key, delta=1) → int` | Decrement a numeric value |
| `cache.adecr()` | `adecr(key, delta=1) → int` | Async variant |

### Key Listing

| Method | Signature | Description |
|--------|-----------|-------------|
| `cache.list()` | `list(prefix, limit=100) → list[str]` | List keys matching prefix |
| `cache.alist()` | `alist(prefix, limit=100) → list[str]` | Async variant |

### TTL Inspection

| Method | Signature | Description |
|--------|-----------|-------------|
| `cache.get_with_ttl()` | `get_with_ttl(key, type_=None, coder=None) → tuple[Any, int \| None]` | Get value with remaining TTL |
| `cache.aget_with_ttl()` | `aget_with_ttl(key, type_=None, coder=None) → tuple[Any, int \| None]` | Async variant |

## TTL and Expiration

Cache entries can have time-to-live (TTL) set in three ways:

### Relative Expiration (`ex`)

Sets expiration in seconds from now:

```python
# Expires in 5 minutes
cache.set("session:abc", data, ex=300)
```

### Absolute Expiration (`ea`)

Sets expiration as a Unix timestamp:

```python
import time

# Expires at a specific time
cache.set("session:abc", data, ea=time.time() + 3600)
```

<Callout type="warning">
Use only one of `ex`, `px`, and `ea`: `px` sets a relative expiration in milliseconds. If all are `None`, the entry never expires. The in-memory backend gives `ex` precedence over `px` and `ea` when multiple values are supplied; do not rely on backend-specific behavior.
</Callout>

## Coders

By default, values are serialized using `orjson`. You can customize serialization with the `coder` parameter or auto-decode to a specific type with `type_`.

### Auto-Decode with `type_`

```python
from pydantic import BaseModel

class User(BaseModel):
    name: str
    email: str

# Store as usual
cache.set("user:123", {"name": "Alice", "email": "alice@example.com"})

# Retrieve and auto-decode to User
user = cache.get("user:123", type_=User)
print(type(user))  # <class 'User'>
```

### Custom Coders

```python
from bedrock.contrib.cache import CacheCoder

class MsgPackCoder(CacheCoder[dict]):
    @staticmethod
    def encode(value: dict) -> bytes:
        import msgpack
        return msgpack.packb(value)

    @staticmethod
    def decode(data: bytes) -> dict:
        import msgpack
        return msgpack.unpackb(data)

# Use the custom coder
cache.set("data:key", {"foo": "bar"}, coder=MsgPackCoder)
result = cache.get("data:key", coder=MsgPackCoder)
```

<Callout type="warning">
Pass either `type_` or `coder` to reads, not both. Passing both for a cached value raises `ValueError`.
</Callout>

## Namespaces

Namespaces group related cache keys under a common prefix. They provide `clear()` and `list()` operations scoped to the namespace.

```python
from bedrock.contrib.cache import cache

# Create a namespace
users = cache.namespace("users")

# Build keys within the namespace
key = users.build_key("user", "123")  # "users:user:123"

# List all keys in the namespace
all_user_keys = users.list(limit=50)

# Clear all keys in the namespace
count = users.clear()
```

### Namespace API

| Method | Signature | Description |
|--------|-----------|-------------|
| `namespace.build_key()` | `build_key(*segments) → str` | Build a fully qualified key |
| `namespace.clear()` | `clear() → int` | Delete all keys in namespace |
| `namespace.aclear()` | `aclear() → int` | Async variant |
| `namespace.list()` | `list(limit=100) → list[str]` | List keys in namespace |
| `namespace.alist()` | `alist(limit=100) → list[str]` | Async variant |
| `namespace.slot()` | `slot(template, ...) → CacheSlot` | Create a typed key slot |

## Slots

Slots are typed key templates with a stable namespace and default TTL policy. They provide type-safe `get()`/`set()`/`delete()`/`exists()` operations.

```python
from bedrock.contrib.cache import cache
from pydantic import BaseModel

class User(BaseModel):
    name: str
    email: str

# Create a typed slot
users_ns = cache.namespace("users")
user_slot = users_ns.slot("user:{user_id}", value_type=User, ttl=300)

# Use the slot
user_slot.set(User(name="Alice", email="alice@example.com"), user_id="123")
user = user_slot.get(user_id="123")  # Returns User instance
user_slot.delete(user_id="123")
exists = user_slot.exists(user_id="123")  # False

# Load from source only when the key is missing, then store it
user = user_slot.get_or_load(lambda: User(name="Alice", email="alice@example.com"), user_id="123")
```

### Slot API

| Method | Signature | Description |
|--------|-----------|-------------|
| `slot.get()` | `get(default=None, **params) → T` | Read the cached value |
| `slot.aget()` | `aget(default=None, **params) → T` | Async variant |
| `slot.get_or_load()` | `get_or_load(loader, *, ex=None, px=None, ea=None, **params) → T` | Read, or load and store on a miss |
| `slot.aget_or_load()` | `aget_or_load(loader, *, ex=None, px=None, ea=None, **params) → T` | Async variant |
| `slot.set()` | `set(value, *, ex=None, px=None, ea=None, **params) → None` | Write a value |
| `slot.aset()` | `aset(value, *, ex=None, px=None, ea=None, **params) → None` | Async variant |
| `slot.delete()` | `delete(**params) → bool` | Delete the cached value |
| `slot.adelete()` | `adelete(**params) → bool` | Async variant |
| `slot.exists()` | `exists(**params) → bool` | Check if value exists |
| `slot.aexists()` | `aexists(**params) → bool` | Async variant |
| `slot.get_with_ttl()` | `get_with_ttl(**params) → tuple[T, int \| None]` | Get value with TTL |
| `slot.aget_with_ttl()` | `aget_with_ttl(**params) → tuple[T, int \| None]` | Async variant |
| `slot.build_key()` | `build_key(**params) → str` | Render the fully qualified key |

<Callout type="info">
Slot templates use Python string format syntax. Parameters are extracted automatically and must be provided when calling `get()`, `set()`, etc.
</Callout>

## Distributed Locks

The cache system provides distributed locks backed by the configured backend. Locks support both sync and async context managers, as well as manual acquire/release.

### Context Manager (Recommended)

```python
from bedrock.contrib.cache import cache

# Sync context manager
with cache.lock("jobs:sync", expire=30, blocking_timeout=5):
    run_job()  # Lock is held here

# Async context manager
async with cache.lock("jobs:async", expire=30, blocking_timeout=5):
    await run_job()  # Lock is held here
```

### Manual Acquire/Release

```python
from bedrock.contrib.cache import cache

lock = cache.lock("jobs:manual", expire=30, blocking=False)

if lock.acquire():
    try:
        run_job()
    finally:
        lock.release()
```

### Lock Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `name` | Required | Logical lock name |
| `expire` | `30` | Lock TTL in seconds |
| `blocking` | `True` | Whether to wait for the lock |
| `blocking_timeout` | `None` | Max seconds to wait (None = forever) |
| `sleep` | `0.1` | Delay between acquisition attempts |
| `prefix` | `"lock"` | Namespace prefix for the lock key |

### Lock API

| Method | Signature | Description |
|--------|-----------|-------------|
| `lock.acquire()` | `acquire(blocking=None, blocking_timeout=None, sleep=None) → bool` | Acquire the lock |
| `lock.aacquire()` | `aacquire(blocking=None, blocking_timeout=None, sleep=None) → bool` | Async variant |
| `lock.release()` | `release() → None` | Release the lock |
| `lock.arelease()` | `arelease() → None` | Async variant |
| `lock.locked()` | `locked() → bool` | Check if lock is held |
| `lock.alocked()` | `alocked() → bool` | Async variant |

## Backends

### InMemoryBackend (Default)

Thread-safe in-process cache. No external dependencies.

```python
cache.configure("memory")
```

| Setting | Default | Description |
|---------|---------|-------------|
| `CACHE_MEMORY_MAX_SIZE` | `10000` | Maximum number of entries |
| `CACHE_MEMORY_DEFAULT_TTL` | `300` | Settings value; cache writes do not apply it automatically |

### RedisBackend

Redis-backed distributed cache. Requires `uv add bedrock-core[cache-redis]`.

```python
cache.configure("redis")
```

| Setting | Default | Description |
|---------|---------|-------------|
| `CACHE_REDIS_URL` | `"redis://localhost:6379/0"` | Redis connection URL |
| `CACHE_REDIS_DB` | `0` | Redis database number |
| `CACHE_REDIS_PASSWORD` | `None` | Redis password |
| `CACHE_REDIS_KEY_PREFIX` | `""` | Default key namespace. `clear()`/`aclear()` require this **or** an explicit `prefix=` argument |
| `CACHE_REDIS_MAX_CONNECTIONS` | `50` | Maximum connections per pool |

<Callout type="warning">
Redis `clear()` and `aclear()` never flush the Redis database. They scan and delete only keys under a prefix. Pass an explicit `prefix=` argument, or configure `CACHE_REDIS_KEY_PREFIX` to a dedicated non-empty namespace. Clearing fails only when **both** the configured prefix and the explicit argument are empty. Applications that relied on unprefixed `flushdb()` must choose a dedicated prefix.
</Callout>

## Exception Hierarchy

All cache exceptions inherit from `CacheError`:

```
CacheError
├── CacheConnectionError      — Backend connection failure
├── CacheSerializationError   — Serialization/deserialization failure
├── BackendNotConfiguredError — Backend not available
├── CacheClearRequiresPrefixError — Redis clear has neither configured nor explicit prefix
└── CacheLockError
    ├── CacheLockAcquisitionError — Lock acquisition failure
    └── CacheLockOwnershipError   — Lock ownership violation
```

```python
from bedrock.contrib.cache import (
    CacheError,
    CacheConnectionError,
    CacheSerializationError,
    BackendNotConfiguredError,
    CacheClearRequiresPrefixError,
    CacheLockError,
    CacheLockAcquisitionError,
    CacheLockOwnershipError,
)
```

## Anti-Patterns

**Don't call `configure()` more than once.** The backend is initialized once. Calling `configure()` again replaces the previous backend without cleanup.

**Don't use the in-memory backend for distributed locks.** `InMemoryBackend` is process-local. Locks only coordinate within a single process. Use `RedisBackend` for cross-process coordination.

**Don't forget TTL for temporary data.** Without `ex`, `px`, or `ea`, entries persist until explicitly deleted or the process restarts. Always set TTL for session data, tokens, and temporary state.

**Don't use `bedrock.cache` as import path.** The canonical import is `from bedrock.contrib.cache import cache`. There is no re-export at the `bedrock` package level.

**Don't mix `type_` and `coder` on reads.** Passing both to a read of a cached value raises `ValueError`. Choose one serialization strategy per call.

**Don't hardcode cache keys.** Use namespaces and slots to organize keys. Raw string concatenation leads to key collisions and makes cache invalidation difficult.
