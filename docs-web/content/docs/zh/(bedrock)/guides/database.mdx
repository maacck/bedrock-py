Bedrock 内置了一套 SQLAlchemy 2.0 数据库层，用于处理 engine 初始化、上下文局部 session、声明式模型以及 Alembic 迁移。整个子系统位于 `bedrock.database` 下。

## 快速开始

定义一个模型，初始化数据库，然后开始查询：

```python
from bedrock.database import db, BedrockModel
from sqlalchemy import Column, String, Integer

class Product(BedrockModel):
    __tablename__ = "products"

    id = Column(Integer, primary_key=True)
    name = Column(String(100), nullable=False)

# Initialize once at process start
db.init()

# 使用事务作用域（退出时解绑 session）
with db.session_scope() as session:
    product = Product(name="Widget")
    session.add(product)
    session.flush()

    # Query back
    all_products = session.query(Product).all()
```

这就是核心使用循环。本页其余部分会介绍配置、完整 API 以及高级模式。

## 配置

数据库设置使用带有 `DATABASE_` 前缀的环境变量。`DbSettings` 是 Pydantic 的 `BaseSettings` 子类，因此会自动从环境中读取配置。

### 环境变量

| 变量 | 类型 | 默认值 | 说明 |
|----------|------|---------|-------------|
| `DATABASE_TYPE` | `str` | `"sqlite"` | 数据库方言（`sqlite`、`postgresql`、`mysql`） |
| `DATABASE_DRIVER` | `str` | `"pysqlite"` | DBAPI 驱动（`pysqlite`、`psycopg2`、`pymysql`） |
| `DATABASE_HOST` | `str \| None` | `None` | 数据库主机（非 SQLite 时必需） |
| `DATABASE_PORT` | `int \| None` | `None` | 数据库端口（非 SQLite 时必需） |
| `DATABASE_USERNAME` | `str \| None` | `None` | 数据库用户名 |
| `DATABASE_PASSWORD` | `SecretStr \| None` | `None` | 数据库密码。不会出现在 `repr` 和校验错误中。 |
| `DATABASE_ASYNC_DRIVER` | `str \| None` | `None` | 异步 DBAPI 驱动（`aiosqlite`、`asyncpg`、`psycopg`、`asyncmy`、`aiomysql`） |
| `DATABASE_MAX_CONNECTIONS` | `int` | `10` | 单个进程的连接上限，包含溢出连接 |
| `DATABASE_POOL_TIMEOUT` | `int` | `30` | 等待连接的秒数 |
| `DATABASE_POOL_SIZE` | `int` | `10` | 连接池常态大小，至少为 1。 |
| `DATABASE_POOL_RECYCLE` | `int` | `1800` | 回收连接前的秒数 |
| `DATABASE_MIGRATION_LOCK_TIMEOUT` | `float` | `30` | 等待迁移锁的秒数。`0` 表示不等待。 |
| `DATABASE_SCHEMA` | `str` | `"bedrock.db"` | 数据库名称或文件路径 |

`MAX_CONNECTIONS` 是单个进程可以同时取出的连接总数。PostgreSQL 和 MySQL 的 engine 会收到 `pool_size`、`pool_timeout`、`pool_recycle`，以及 `max_overflow = MAX_CONNECTIONS - POOL_SIZE`。`MAX_CONNECTIONS` 必须大于或等于 `POOL_SIZE`，更小的值会抛出 `DatabaseConfigurationError`，错误信息会同时写明这两个设置。`POOL_SIZE` 小于 1 同样会抛出 `DatabaseConfigurationError`，因为 SQLAlchemy 把 0 视为不限制连接池大小，上限会失效。SQLite engine 继续忽略连接池设置。

默认值（`POOL_SIZE=10`、`MAX_CONNECTIONS=10`）把单个进程限制在 10 个连接。此前 SQLAlchemy 还会附加默认的 10 个溢出连接，因此同样的默认值实际允许 20 个连接。部署如果依赖那部分溢出容量，需要把 `DATABASE_MAX_CONNECTIONS` 提高到 `DATABASE_POOL_SIZE` 之上。

`PASSWORD` 是 Pydantic 的 `SecretStr`。传入普通字符串会被保存为 secret。`repr(settings)` 和校验错误不会包含密码或拼好的 URL。URL 由 `sqlalchemy.engine.URL.create` 生成，用户名和密码里的 `@`、`:`、`/`、`%` 会正确转义并可以还原。只在真正打开连接的地方调用 `settings.PASSWORD.get_secret_value()`。

将 `DbSettings` 实例直接传给 `db.init()`：

```python
from bedrock.database import db, DbSettings

settings = DbSettings(
    TYPE="postgresql",
    DRIVER="psycopg2",
    HOST="localhost",
    PORT=5432,
    USERNAME="admin",
    PASSWORD="secret",
    SCHEMA="myapp",
)

db.init(settings=settings)
```

你也可以完全覆盖连接 URL：

```python
db.init(url="postgresql+psycopg2://admin:secret@localhost:5432/myapp")
```

## DatabaseManager

`db` 单例是一个 `DatabaseManager` 实例。它持有 engine、session factory 和 settings。所有访问都通过该对象进行。

### API 参考

| 方法 / 属性 | 签名 | 说明 |
|-------------------|-----------|-------------|
| `db.init()` | `init(url: str \| None = None, settings: DbSettings \| None = None)` | 初始化 engine 和 session factory。在进程启动时调用一次。 |
| `db.engine` | `property → Engine` | SQLAlchemy engine。未初始化时会抛出 `DatabaseNotConfiguredError`。 |
| `db.session` | `property → Session` | 当前上下文绑定的 session。没有绑定时抛出 `SessionNotBoundError`。 |
| `db.session_factory` | `property → SessionFactory` | 底层 session factory。 |
| `db.settings` | `property → DbSettings` | 解析后的数据库 settings。 |
| `db.set_session(session)` | `set_session(session: Session)` | 将现有 session 绑定到当前执行上下文。 |
| `db.clear_session()` | `clear_session()` | 关闭并解绑当前上下文局部 session。 |
| `db.session_scope()` | `contextmanager → Session` | 事务作用域，自动提交/回滚。绑定到上下文。也可以用作装饰器。 |
| `db.independent_session()` | `contextmanager → Session` | 隔离事务，不绑定到上下文。 |
| `db.aengine` | `property → AsyncEngine` | 使用 `init()` 已解析的 URL，只把驱动换成 `DATABASE_ASYNC_DRIVER`。 |
| `db.asession` | `property → AsyncSession` | 当前上下文绑定的异步 session，使用与 `db.session` 不同的上下文变量。没有绑定时抛出 `SessionNotBoundError`。 |
| `db.asession_scope()` | `async context manager → AsyncSession` | 异步事务作用域，提交、回滚和禁止嵌套的规则与 `session_scope()` 相同。也可以用作 `async def` 的装饰器。 |
| `db.aindependent_session()` | `async context manager → AsyncSession` | 不绑定 `db.asession` 的异步事务。 |
| `db.close()` | `close()` | 释放同步 engine。已创建的异步 engine 仍可使用。可以重复调用。之后可以再次 `init()`。 |
| `db.aclose()` | `async aclose()` | 释放异步 engine。同步 engine 仍可使用。可以重复调用。 |

### 错误处理

在调用 `db.init()` 之前访问 `db.engine`、`db.session` 或 `db.settings` 会抛出 `DatabaseNotConfiguredError`。使用这些属性前务必先初始化数据库。

当前上下文没有绑定 session 时读取 `db.session` 或 `db.asession` 会抛出 `SessionNotBoundError`（`BedrockExc` 的子类）。框架不会隐式创建 session：请在入口处打开作用域。

## Session 管理

Bedrock 使用由 `ContextVar` 支撑的上下文局部 session。新异步任务会继承创建者的上下文，包括已绑定的 session；应在任务和请求边界清理或单独建立绑定，避免并发共享 session。

### 工作方式

`SessionFactory` 对 SQLAlchemy 的 `sessionmaker` 做了封装。`db.session` 只返回 `ContextVar` 中已绑定的 session，从不自行创建。绑定由入口负责：

| 入口 | 绑定方式 |
|------|----------|
| 脚本、CLI 命令、自定义 worker、WebSocket 处理函数、启动钩子 | `with db.session_scope():` 或 `@db.session_scope()` |
| FastAPI HTTP 请求 | `bedrock-fastapi` 的 `DbSessionMiddleware` / `AsyncDbSessionMiddleware` |
| 测试 | 在测试中 `with db.session_scope():`；`bedrock.testing` 的 `db_session` fixture 负责回滚 |
| 由其他框架管理的 session | `db.set_session(...)` |

Service 读取 `db.session` 并负责提交，自身不打开作用域：

```python
from bedrock.database import db

# service.py
def create_product(name: str) -> None:
    db.session.add(Product(name=name))
    db.session.commit()

# 入口
db.init()
with db.session_scope():
    create_product("Widget")

create_product("Gadget")  # 抛出 SessionNotBoundError：没有打开作用域
```

### 使用 `session_scope()` 管理事务

推荐使用 `session_scope()` 来管理事务。它会创建一个新 session，绑定到当前上下文，并在正常退出时自动提交，异常时自动回滚：

```python
from bedrock.database import db

db.init()

# 成功时自动提交
with db.session_scope() as session:
    product = Product(name="Widget")
    session.add(product)
    # 块正常退出时 session 自动提交

# 异常时自动回滚
try:
    with db.session_scope() as session:
        session.add(Product(name="Gadget"))
        raise ValueError("出错了")  # 回滚
except ValueError:
    pass  # "Gadget" 永远不会被持久化
```

**关键行为：**
- 将 session 绑定到 `ContextVar`，块内可正常使用 `db.session`
- 正常退出时提交，任何异常（包括 `BaseException`）时回滚
- 退出时始终关闭 session 并重置 `ContextVar`
- 如果在已绑定 session 的上下文中调用会抛出 `RuntimeError`（防止嵌套）

### 装饰入口函数

`session_scope()` 和 `asession_scope()` 也可以用作装饰器。每次调用都会打开新的作用域，所以每次调用都有自己的 session 和事务。装饰器可以在 `db.init()` 之前应用，因为数据库只在函数被调用时才会用到：

```python
from bedrock.database import db

@db.session_scope()
def import_products(path: str) -> None:
    for name in read_names(path):
        db.session.add(Product(name=name))

@db.asession_scope()
async def sync_inventory() -> None:
    await refresh_stock(db.asession)
```

注意括号：写 `@db.session_scope()`，不是 `@db.session_scope`。函数返回值原样返回。不要装饰会在已绑定 session 时被调用的函数（例如请求内调用的 service）：嵌套的作用域会抛出 `RuntimeError`。

### 使用 `independent_session()` 进行独立事务

对于需要写入但不影响当前事务的副作用操作，使用 `independent_session()`。它创建一个**不**绑定到 `ContextVar` 的隔离 session：

```python
from bedrock.database import db

db.init()

with db.session_scope() as session:
    # 主事务
    order = Order(total=100)
    session.add(order)

    # 在独立事务中写入审计日志
    with db.independent_session() as audit_session:
        audit_log = AuditLog(action="order_started")
        audit_session.add(audit_log)
        # 独立提交 — 不影响外部 session

    # db.session 仍然返回外部 session
    assert db.session is session
```

**`independent_session()` 适用场景：**
- 审计日志（即使主事务回滚也必须持久化）
- 以独立事务发布事件（事务性 outbox 则必须与主事务共享同一事务）
- 需要读取调用方未提交数据之外的数据
- 需要独立事务生命周期的后台任务

### 异步 Session

异步服务使用带 `a` 前缀的同一套作用域规则。设置 `DATABASE_ASYNC_DRIVER`，并安装提供该驱动的 extra：

| 驱动 | 安装 |
|--------|---------|
| `aiosqlite` | `pip install 'bedrock-core[async-sqlite]'` |
| `asyncpg` | `pip install 'bedrock-core[async-postgresql]'` |
| `asyncmy` | `pip install 'bedrock-core[async-mysql]'` |
| `psycopg`、`aiomysql` | 直接安装驱动包（`pip install psycopg` / `pip install aiomysql`） |

`db.asession_scope()` 在正常退出时提交，在任何异常时回滚，并且在当前上下文已经绑定异步 session 时拒绝嵌套。`db.aindependent_session()` 不会绑定 `db.asession`。异步 session 使用单独的上下文变量，同一任务里的同步 session 保持不变。缺少驱动包时会抛出 `DatabaseConfigurationError`，并在错误信息中写明需要安装的 extra。

```python
from bedrock.database import db, DbSettings

db.init(settings=DbSettings(ASYNC_DRIVER="aiosqlite"))

async with db.asession_scope() as session:
    session.add(Product(name="Widget"))

await db.aclose()
db.close()
```

### 关闭 Engine

同步 engine 调用 `db.close()`，异步 engine 调用 `await db.aclose()`。两边都创建过时，两个都要调用。对同一侧重复调用不会再做额外释放。`close()` 之后，同步访问会抛出 `DatabaseNotConfiguredError`，直到再次 `db.init()`；已经创建的异步 engine 仍可使用。`aclose()` 之后，同步 engine 仍可使用；若同步配置还在，下一次异步访问会重新构建异步 engine。这两个方法不会关闭模块注册表。停止进程时请调用 `bedrock.shutdown()`（或 `await bedrock.ashutdown()`）：它会先停止所有模块，再各调用一次 `db.close()` 以及（存在异步 engine 时）`db.aclose()`，因此即使某个模块失败，两个连接池也会在所有模块钩子之后被释放。从未初始化的数据库不会被处理。在运行中的事件循环里且存在异步 engine 时，请使用 `await bedrock.ashutdown()`；`bedrock.shutdown()` 会在改变任何状态之前抛出 `ModuleAsyncRequiredError`。

`db.init()` 会释放上一个同步 engine。已经打开过连接的异步 engine 不会在这里同步释放：那种关闭发生在事件循环之外，会以 `MissingGreenlet` 失败。需要关闭该异步 engine 时，先 `await db.aclose()` 再调用 `db.init()`。尚未打开连接的异步 engine 会在 `init()` 中释放。

### 绑定外部 Session

当你使用会自行管理 session 的框架（例如 FastAPI 的依赖注入）时，可以绑定一个现有 session：

FastAPI 用户请优先使用 [FastAPI 集成](/docs/integrations/fastapi#数据库-session)中的数据库 session 中间件。

```python
from bedrock.database import db

# Bind a session from an external source
db.set_session(framework_session)
try:
    product = db.session.query(Product).first()
finally:
    db.clear_session()  # 关闭 session，然后解绑
```

## BedrockModel

所有 Bedrock 模型都继承自 `BedrockModel`，它将 SQLAlchemy 的 `DeclarativeBase` 与用于常见操作的 `CrudMixin` 结合在一起。

### 内置方法

| 方法 / 属性 | 说明 |
|-------------------|-------------|
| `.dict()` | 返回包含所有列值的字典 |
| `.update(**kwargs)` | 使用关键字参数设置属性 |
| `.delete()` | 从其所在 session 中删除该实例 |
| `.verbose_name` | 以可读标签形式返回类名 |
| `.__repr__()` | 返回 `<ClassName #id>` 格式 |

### 示例

```python
from bedrock.database import BedrockModel
from sqlalchemy import Column, String, Integer

class Product(BedrockModel):
    __tablename__ = "products"
    __filterable_fields__ = ["name", "price"]

    id = Column(Integer, primary_key=True)
    name = Column(String(100), nullable=False)
    price = Column(Integer, default=0)

# Create and use
product = Product(name="Widget", price=999)
product.dict()  # {"id": None, "name": "Widget", "price": 999}

# Update attributes
product.update(price=1499)

# Delete (must be attached to a session)
session.add(product)
session.commit()
product.delete()
session.commit()
```

### 默认值

BedrockModel 会监听 `init` 事件，并在构造函数结束前应用列默认值。可调用默认值会以实例作为参数进行调用；显式传入的关键字参数优先于默认值。

## 查询构建器

`search_filter_sort_paginate` 函数可构建带有过滤、排序、分页和自动 join 的查询。它返回一个包含 `items`、`total` 和 `page_info` 的字典。

### 可过滤字段

`filter_specs`、`sort_key` 和 `group_by` 通常来自客户端，因此只能引用模型公开的字段。主键始终可用；其他列、hybrid 属性、association proxy 和关系都必须列在 `__filterable_fields__` 中：

```python
class Order(BedrockModel):
    __tablename__ = "orders"
    __filterable_fields__ = ["status", "customer"]  # "customer" is a relationship


class Customer(BedrockModel):
    __tablename__ = "customers"
    __filterable_fields__ = ["name"]  # password_hash stays hidden
```

- 点号或冒号路径的每一跳都按所在模型检查：`customer.name` 需要 `Order` 列出 `customer`，`Customer` 列出 `name`。
- `count_pk` 必须是主键。
- 其他名称会抛出 `BadFilterFormatError`（"Field `x` is not filterable on Order"）。隐藏字段和不存在的字段抛出相同的错误，客户端无法借此探测表结构。
- 如果应用在调用查询构建器之前已经校验了字段名，可以设置 `__filterable_fields__ = "__all__"`，关闭该模型的检查。通过路径访问的关联模型仍按各自的 `__filterable_fields__` 检查，需要时也给它们设置 `"__all__"`。使用 `"__all__"` 后，保护敏感列由应用自己负责。
- `sqla_filters` 和 `q` 使用的 `__searchable_columns__` 由你的代码编写，不受此检查。

### 基本用法

```python
from bedrock.database.service import search_filter_sort_paginate

result = search_filter_sort_paginate(
    db_session=db.session,
    model=Product,
    filter_specs=[
        {"field": "name", "op": "ilike", "value": "%widget%"},
    ],
    sort_key="name",
    sort_dir="asc",
    page=1,
    limit=20,
)

result["items"]     # List of Product instances
result["total"]     # Total count matching filters
result["page_info"] # Pagination metadata
```

### 异步 Session

在 `async def` 的 service 中，配合 `db.asession` 调用 `asearch_filter_sort_paginate`。它的参数和返回的字典与同步版本相同：

```python
from bedrock.database.service import asearch_filter_sort_paginate

result = await asearch_filter_sort_paginate(
    db_session=db.asession,
    model=Product,
    filter_specs=[{"field": "name", "op": "ilike", "value": "%widget%"}],
    page=1,
    limit=20,
)
```

异步 session 不能延迟加载关系。需要读取 `result["items"]` 上的关系时，通过 `options` 预先加载，例如 `options=[selectinload(Product.tags)]`。

| 属于 | `in` | 值在列表中 |

### 布尔组合器

使用 `or` 和 `and` 组合多个过滤条件：

```python
filter_specs = {
    "or": [
        {"field": "name", "op": "ilike", "value": "%widget%"},
        {"field": "price", "op": "<", "value": 100},
    ]
}

filter_specs = {
    "and": [
        {"field": "name", "op": "ilike", "value": "%widget%"},
        {"field": "price", "op": ">=", "value": 50},
    ]
}
```

将 `sort_key` 作为字符串或元组列表传入：

```python
# Single sort

# Multiple sorts

```

### 分页

通过 `page`、`limit` 和 `show_all` 控制结果：

```python
result = search_filter_sort_paginate(
    db_session=db.session,
    model=Product,
    page=2,       # Second page
    limit=10,     # 10 items per page
)

# Or fetch everything
result = search_filter_sort_paginate(
    db_session=db.session,
    model=Product,
    show_all=True,
)
```

`limit` 必须是 1 到 1000 的整数，即使 `show_all=True` 也不例外；无效值会抛出 `InvalidQueryLimitError`。

`page_info` 字典包含：

| 键 | 说明 |
|-----|-------------|
| `total` | 匹配记录总数 |
| `limit` | 每页条目数 |
| `offset` | 当前偏移量 |
| `page` | 当前页码 |
| `query` | 搜索字符串，未指定时为空字符串 |
| `filters` | 传入的过滤条件，未指定时为空列表 |
| `has_more` | 是否还有更多页面 |
| `paginated` | 是否启用了分页 |

### 关联模型过滤

可通过点号语法对 join 进行过滤，或通过冒号语法使用 `any()` / `has()` 跨关系过滤：

```python
# Dot notation: joins the related model
{"field": "category.name", "op": "eq", "value": "Electronics"}

# Colon notation: uses any() for collections, has() for scalars
{"field": "category:name", "op": "eq", "value": "Electronics"}
```

两种写法都要求 `Product.__filterable_fields__` 包含 `category`，且关联模型的 `__filterable_fields__` 包含 `name`（参见[可过滤字段](#可过滤字段)）。

## 迁移

Bedrock 对 Alembic 做了按模块分支的封装。每个应用都有自己的 Alembic 分支，并以其导入路径作为标识。`MigrationsManager` 负责处理版本创建、升级、降级和 schema stamping。

完整的迁移 CLI 参考见 [CLI 参考 — 数据库命令](/docs/guides/cli#database-commands-bedrock-db)。

### 通过代码使用

```python
from bedrock.module import apps
from bedrock.database.migrations_manager import MigrationsManager

migrations = MigrationsManager(
    registry=apps,
    database_url=db.settings.SQLALCHEMY_DATABASE_URI,
)

# Create a new revision
migrations.revision("myapp.users", "add email column")

# Apply migrations
migrations.upgrade("myapp.users")

# Check current state
migrations.current("myapp.users")

# View history
history = migrations.get_history("myapp.users")
```

### 分支归属

每个应用的 migrations 目录都会在操作前进行审计。如果某个版本文件声明的分支标签与应用导入路径不匹配，就会抛出 `BranchOwnershipError`。这可以防止跨应用的版本树污染。

### 首次安装

当应用分支在数据库中没有已应用的版本时，`ensure_schema()` 会根据 SQLAlchemy metadata 创建该应用的表，并将分支 stamp 到 head。即使存在版本文件，首次安装也无需执行迁移脚本。

### 迁移锁

`upgrade` 和 `downgrade`（包括 `ensure_schema()` 和 `uninstall()`）会获取数据库锁，避免两个进程同时迁移同一个数据库。

| 方言 | 锁 | 等待 |
|---------|------|------|
| PostgreSQL | `pg_try_advisory_lock` | 轮询直到 `DATABASE_MIGRATION_LOCK_TIMEOUT`（默认 30 秒） |
| MySQL、MariaDB | `GET_LOCK` | 同一超时时间，向上取整到整秒 |
| SQLite | 无 | 只在单个进程中运行迁移 |

超时会抛出 `MigrationError`。这个管理器不为 SQLite 提供跨进程锁。

### `bedrock db check`

`bedrock db check <app>` 会打印该应用，以及已经带有迁移脚本的其他已安装应用的当前版本和 head 版本。它不修改数据库，也不会创建 Alembic 版本表。任一分支处于 `behind` 或 `unknown` 时，进程以状态码 1 退出。`unknown` 包含从未执行过迁移的数据库。可以把它用作对外提供流量之前的部署门禁。参见 [CLI 参考 — 数据库命令](/docs/guides/cli#database-commands-bedrock-db)。

## 模型事件

Bedrock 不封装 ORM 事件。直接注册 SQLAlchemy 监听器，并按需要选择触发阶段：

```python
from sqlalchemy import event
from sqlalchemy.orm import Session

# INSERT 执行之后：主键已经赋值。额外的 SQL 用 `connection` 执行，不要修改 session。
@event.listens_for(Catalog, "after_insert", propagate=True)
def catalog_inserted(mapper, connection, target):
    ...

# flush 之前：在这里加入 session 的对象会在同一个事务中一起 flush。
@event.listens_for(Session, "before_flush")
def audit_catalog(session, flush_context, instances):
    for obj in session.new:
        if isinstance(obj, Catalog):
            session.add(AuditLog(action="catalog_created"))
```

`after_update` / `after_delete`（以及对应的 `before_*`）用法相同。`propagate=True` 让子类也会触发。全部钩子及其限制见 SQLAlchemy 的 [ORM 事件文档](https://docs.sqlalchemy.org/en/20/orm/events.html)。

## 架构

数据库模块按职责拆分为多个聚焦文件：

```
bedrock/database/
├── __init__.py            # Public exports
├── base.py                # BedrockModel (DeclarativeBase + CrudMixin)
├── config.py              # DbSettings (env-prefixed BaseSettings)
├── connection.py          # Engine and session factory builders
├── filters.py             # Filter operators and boolean combinators
├── manager.py             # DatabaseManager singleton (db)
├── migrations/            # Alembic env.py and script.py.mako
├── migrations_manager.py  # Per-module Alembic orchestration
├── service.py             # search_filter_sort_paginate query builder
├── session_factory.py     # Context-local sessions via ContextVar
└── utils.py               # Model registry helpers
```

## 反模式

**避免在工作进行中重新初始化 `db`。** `db.init()` 支持替换：先构建新的同步 engine，再清理当前上下文的同步 session 并释放上一个同步 engine。如果异步 engine 已经打开过连接，先 `await db.aclose()` 再 `init()`，让这些连接在事件循环上关闭。替换前其他上下文必须自行管理其 session。

**不要在初始化前访问 `db.session`。** 这会抛出 `DatabaseNotConfiguredError`。务必先调用 `db.init()`。

**不要在作用域之外读取 `db.session`。** 这会抛出 `SessionNotBoundError`。请在入口处用 `db.session_scope()` 或 FastAPI 中间件绑定 session；service 只负责读取。

**不要忘记清理自己绑定的 session。** 用 `db.set_session()` 绑定的 session 会一直保持绑定，直到调用 `db.clear_session()`。请在 `finally` 中调用。

**不要在 service 或 model 层中放入 HTTP 类型。** Request 和 Response 对象应位于适配器边界，而不应进入业务逻辑。

**不要绕过 `ModuleRegistry.install()` 来执行迁移。** registry 会处理依赖顺序和生命周期钩子，手动加载模块会跳过这些机制。

**不要硬编码数据库 URL。** 使用环境变量或 `DbSettings`，让配置保持在代码之外。

**不要在模块级别直接实例化 settings（如果环境变量可能尚未就绪）。** 使用 `bedrock.conf` 中的 `SettingsProxy` 包装模块级单例以延迟初始化。

**不要在核心代码中导入 `contrib` 模块。** 核心运行时不能依赖 contrib 包。
